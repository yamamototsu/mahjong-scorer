## 新しいセッションでの始め方

**このリポジトリで Claude Code のセッションを開くだけです。**
資料を添付する必要も、コマンドを打つ必要もありません。

`.claude/hooks/session-start.sh` が自動で `dev/setup.sh` を実行し、
約1分で以下が揃った状態からスタートします。

- ビルド・検証ツールを `../mj-tools`（既定 `/home/user/mj-tools`）へ配置
- Babel / React / playwright-core を `npm install`
- 試しに1回ビルドして動作確認

手動でやり直したいときは `bash dev/setup.sh`。何度実行しても安全です。

node /home/user/mj-tools/layout-check.js local.html [actions.js] # レイアウト検査

`shot.js` が「JSエラーあり」と出たらその変更は不合格。

**画面に手を入れたら指摘ゼロにしてからコミットすること。**

Chromium は Claude Code on the web の環境に同梱（`/opt/pw-browsers/chromium`）。
`playwright install` は不要です。

## 変更してはいけない設計判断

### 起動速度
JSXの変換は**必ずビルド時**に行う。ブラウザでBabelを動かすと起動に約10秒かかる
（対処前9.93秒 → 対処後0.16秒）。`type="text/babel"` を復活させないこと。

### 卓上モードのレイアウト
- 卓は**正方形**（`aspect-ratio: 1/1`）で画面中央に配置
- 中の要素はすべて `cqmin` 単位（卓の一辺に対する比率）。
  固定pxに戻すと端末サイズによって枠同士が重なる
- パネル 38%×26%、卓のふちからの余白 3%、中央の枠 25%
- 対局中はページのスクロールを無効化し、ずれても中央に戻す
- 席の回転（🔄）は**反時計回り**

### UI方針
- ウィザードは1画面1問。複数項目を1画面に詰め込まない
- 「対局終了」は自然な終局時の結果画面にのみ置く（途中終了はルール確認モーダル内）
- 説明ボタンに「？」や括弧は付けない
- 枠と枠は必ず離す（接触させない）

### 用語
カタカナは **アガリ / ホウジュウ** のみ。
連荘・流局・役満・満貫・本場・供託などは漢字のまま。

## 実装済み機能

### 対局メニュー
1. 東風戦・半荘戦（1回きり）
2. リーグ戦（複数回の通算成績）
3. 1局戦（翻・符から点数計算）
4. 対局履歴

### セットアップ（参加者 → 席決め → 形式 → ルール → 確認）
- **グループ**: 4人の組み合わせを保存してワンタップ呼び出し
- **席の並べ替え**: 「席を1つずらす」「ランダムに並べ替え」
- **前回と同じルールで始める**: 確認画面まで一気に飛ぶ
- 確認画面は**卓の配置**で座る位置を表示

### 卓上モード
- 4人のパネルが実際の座席位置に配置（対面は180度回転）
- リーチ宣言で即1,000点減算・供託に加算
- アガリ入力: あがった人（最大3人）→ ツモ/ロン → 翻 → 符 → 確認
- 複数ロンがルールを超えるとモーダルで確認（その場でルール変更も可）
- 流局: テンパイ選択、ノーテン罰符3,000点、連荘判定
- 点数を**長押し**で変動履歴（内訳を項目別に色分け）
- サイコロ、局・本場・供託の表示、画面スリープ防止
- 局の修正: アガリも流局も後から修正可（本場・供託は維持）

### ルール設定（設定 / セットアップ / リーグ の3か所で共通）
流局時の親（3択）、複数ロン（3択）、食いタン、後付け、切り上げ満貫、
オーラス親トップで終了、トビで終了、持ち点・返し点、ウマ（5種）。
「ウマ・オカとは」「それぞれのルールの説明を見る」の解説パネル付き。

### リーグ戦
名前・メンバー（4人以上）・終わり方（回数2〜100 / 期間）・ウマオカ・全ルール。
形式は対局ごとに選択。メンバーが4人ちょうどなら全員が自動選択。
pt計算は 五捨六入 → オカ → ウマ。同点は起家に近い席が上位。

### 練習問題
用語問題集（88語）／役一覧／飜数・役名テスト／符計算講座／
点数問題集（4翻以下160パターン）／点数早見表

### 符計算ガイド
- リーチ済みなら「鳴きましたか？」を省略して門前で計算
- 鳴きありなら平和・七対子を非表示、代わりにクイピン形のショートカット（30符固定）
- 役ピッカー: リーチ自動チェック、ツモなら門前清自摸和も自動、ドラ・裏ドラを別カウント

## 検証済みの内容

- **点数計算エンジン**: 3者照合で283マス一致、エッジケース25件合格
- **符計算**: クイピン形・平和・七対子の各経路を検算
- **ウマ・オカ**: 持ち点×返し点の全組み合わせ×ウマ5種でpt合計がゼロ
- **変動履歴**: 履歴の再現と実際の点数が4パターンで一致
- **五捨六入**: 1,280通りの組み合わせで合計ゼロ
- **符の選択肢**: 翻数的にありえない20符・25符を除外

### 2026-08-21 の点検（レイアウト／ルール／第三者の3体＋総合監督）
- **点数早見表**: 子ロン/親ロン/子ツモ/親ツモ × 11符 × 1〜4翻 = 166件が全一致
- **境界・特殊**: 20符平和ツモ・25符七対子・切り上げ満貫・満貫〜トリプル役満・三人麻雀 約90件が全一致
- **ウマ・オカのゼロサム**: 持ち点20,000〜45,000の全組み合わせ×ウマ5種×四人/三人 = 105,300件で残差0
- **実機操作**: リーチ棒・本場・供託・ノーテン罰符の受け渡しを半荘の通し操作で検算し一致
- **四人麻雀のデグレなし**: 卓上モードと順位・点差ビューが変更前とピクセル単位で一致
- 素点が100点単位のときpt合計が±1ずれることがある（約33%。五捨六入の特性で、以前から同じ）
