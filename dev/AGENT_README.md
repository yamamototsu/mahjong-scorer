## ビルドと検証（あなたのworktreeのルートで実行）

ツール一式はセッション開始時に `dev/setup.sh` が `/home/user/mj-tools` へ用意する
（手動でやり直すときは `bash dev/setup.sh`）。

```bash
node /home/user/mj-tools/build.js .          # JSX構文チェック＋index.html/local.html生成
node /home/user/mj-tools/shot.js local.html out.png            # 390×844で描画、JSエラー検出
node /home/user/mj-tools/shot.js local.html out.png actions.js # 操作してから撮影
```
- actions.js の形式: `module.exports = async (page) => { await page.click('text=対局メニューのボタン名'); }`
- shot.js が「JSエラーあり」と出たら**その変更は不合格**。修正するか取り消すこと。
- 変更前後のスクリーンショットを撮って目視比較すること。
- 対局画面まで進む導線（2026-08-26 に実機で再確認）:
  `対局をはじめる` → `四人麻雀` → `半荘戦` → `初期設定ルールでメンバー決定へ` → `クイックスタート`

## レイアウト検査（ユーザー指示・毎回必須）

**画面に手を入れたら、必ず `node /home/user/mj-tools/layout-check.js <local.htmlのパス> [actions.js]`
を実行し、指摘ゼロにしてからコミットすること。** 目視だけで済ませないこと。
検査するのは次の4点で、いずれも過去に実際の不具合が出ている:

| 観点 | 落ちる例 |
|---|---|
| **重なり** | 「アガリ」の枠に固定の高さ3.2%が入り、文字がはみ出して点数と重なっていた |
| **はみ出し** | 親の枠から子の文字が出る。画面の外に要素が出る |
| **余白（マージン）** | 枠と枠が接触する。HANDOVERの「枠と枠は必ず離す」に反する |
| **詰まり（パディング）** | 文字が枠のふちに貼りつく。タップ領域が小さすぎる |

さらに手作業でも確認すること:
- **幅を変えて確認**: 280 / 320 / 390 / 430px。狭い幅で崩れることが多い。
- **文字の折り返し**: 「ルー/ル」のように単語の途中で折り返していないか。
  行末に区切り記号（｜など）だけが残っていないか。
- **極小文字**: 10px未満は原則NG。読めるか実機サイズで確認する。
- **卓上モードは cqmin**: 固定pxを入れると端末サイズで隣の要素と大小が逆転する。

## 変更してはいけない設計判断（HANDOVER より・厳守）
- JSX変換はビルド時に行う。`type="text/babel"` を復活させない。
- 卓上モード: 卓は正方形・中央配置、内部要素は cqmin 単位（固定pxにしない）、
  パネル38%×26%・卓のふちからの余白3%・中央の枠25%、席の回転は反時計回り。
- ウィザードは1画面1問。「対局終了」は自然な終局の結果画面のみ。
- 説明ボタンに「？」や括弧を付けない。枠と枠は必ず離す。
- カタカナは「アガリ／ホウジュウ」のみ。連荘・流局・役満・満貫・本場・供託などは漢字。

## 立入禁止区域（別セッションが並行作業中のため）
- **順位・点差ビュー（スコアボード表示）とその矢印表示まわり**は変更しない。
  （リーグ・対局中の順位表示、点差の▲▼矢印などのリファクタリングが別セッションで進行中）

## 作業ルール
- 迷う変更・大きい変更は**実装せず報告に回す**。確実で小さい改善だけをコミットする。
- コミットは変更1件ごとに分け、メッセージは日本語で
  「どの画面・機能」を触ったか明記（例: `ルール確認画面: ○○の説明を実装に合わせ修正`）。
- **git push は絶対にしない**。ローカルコミットまで。
- コミットメッセージや報告にAIモデル名を書かない。

## 最終報告に必ず含めるもの
1. `git rev-parse --show-toplevel && git rev-parse --abbrev-ref HEAD && git log --oneline origin/main..HEAD` の結果
2. 各コミットの内容と理由（1〜2文ずつ）
3. 検証方法（実行したコマンド、撮ったスクリーンショットのパス）
4. 「報告のみ」とした発見事項のリスト（重要度つき）
