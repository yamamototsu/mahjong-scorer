## レイアウト検査（ユーザー指示・毎回必須）

**画面に手を入れたら、必ず `node /home/user/mj-tools/layout-check.js <local.htmlのパス> [actions.js]`
を実行し、指摘ゼロにしてからコミットすること。** 目視だけで済ませないこと。
検査するのは次の4点で、いずれも過去に実際の不具合が出ている:

| 観点 | 落ちる例 |
|---|---|
| **重なり** | 「アガリ」の枠に固定の高さ3.2%が入り、文字がはみ出して点数と重なっていた |
| **はみ出し** | 親の枠から子の文字が出る。画面の外に要素が出る |
| **余白（マージン）** | 枠と枠が接触する。HANDOVERの「枠と枠は必ず離す」に反する |
| **詰まり（パディング）** | 文字が枠のふちに貼りつく。タップ領域が小さすぎる |

さらに手作業でも確認すること:
- **幅を変えて確認**: 280 / 320 / 390 / 430px。狭い幅で崩れることが多い。
- **文字の折り返し**: 「ルー/ル」のように単語の途中で折り返していないか。
  行末に区切り記号（｜など）だけが残っていないか。
- **極小文字**: 10px未満は原則NG。読めるか実機サイズで確認する。
- **卓上モードは cqmin**: 固定pxを入れると端末サイズで隣の要素と大小が逆転する。

## 変更してはいけない設計判断（HANDOVER より・厳守）
- JSX変換はビルド時に行う。`type="text/babel"` を復活させない。
- ファイル内で定義した画面コンポーネント（RuleCheckModal・YakuPicker など）は
  `<X />` ではなく `{X()}` で呼ぶ。JSX要素にすると再描画のたびに型が
  変わって React が作り直し、スクロール位置が 0 に戻る。
  （2026-08-28 に YakuPicker でも同じ不具合が出て修正した）
- 卓上モード: 卓は正方形・中央配置、内部要素は cqmin 単位（固定pxにしない）、
  パネル38%×26%・卓のふちからの余白3%・中央の枠25%、席の回転は反時計回り。
- ウィザードは1画面1問。「対局終了」は自然な終局の結果画面のみ。
- 説明ボタンに「？」や括弧を付けない。枠と枠は必ず離す。
- カタカナは「アガリ／ホウジュウ」のみ。連荘・流局・役満・満貫・本場・供託などは漢字。

## 配布のしかたの切り替え（DIST）
`dev/mahjong-scorer.jsx` の先頭近くにまとめてある。

| 定数 | 意味 |
| --- | --- |
| `DIST` | `"web"`＝URLを開いて使ってもらう（いま）／`"native"`＝ストアのアプリとして配る |
| `STORE_URL` | ストア配布になったら、ここにストアのURLを入れる |
| `APP_URL()` | 今いる場所を返す。`file://` のときだけ公開先のURLを返す |
| `SHARE_TITLE` / `SHARE_TEXT` / `SHARE_URL()` | 友達に送る中身。直すのはここだけ |

- `DIST = "native"` にすると「ホーム画面に追加」の案内が全部消え、
  「このアプリを友達に教える」が `STORE_URL` を送るようになる。
  画面側に条件を書き足す必要はない。
- ブラウザのタブで開かれているかは `isStandalone()` で判定する。
  ホーム画面から開いていれば案内は出ない（`DIST` が web のままでも）。

## ストア公開に向けて入れた仕組み（2026-10-29）
- **React は `vendor/` に同梱**（cdnjs は使わない）。初回に圏外・CDN障害でも真っ黒にならない。
  `build.js` が無ければ node_modules からコピーする。sw.js の SHELL にも入っている。
- **エラーの受け皿** `AppGuard`（build.js のテンプレート内）。描画で例外が出ても
  「もう一度開く／記録を書き出す」の画面になる。
- **履歴を足すときは `mergeIntoHistory` を通す**。外から来た対局は `sanitizeGame` で形を確かめ、
  `histRef` で最新の履歴に足す（古い `gameHistory` を土台に `setGameHistory` すると取り込みが消える）。
- **Android の戻るボタン**は `appBackRef`（pushState/popstate）。画面の「← 戻る」を押したのと同じ動きにし、
  対局中は保留の確認、終局画面（記録前）は止める。新しいモーダルを足したら appBackRef で閉じられるようにする。
- **プライバシーポリシー**は `privacy.html`（アプリと同じ場所）。sw.js はアプリ本体（`/` と `index.html`）
  だけを本体として保存するので、ほかのページを置いても圏外起動は壊れない。
- **オンラインのデータの削除**は 設定 → このアプリについて。Firebase のルール（`dev/firebase-rules.json`）を
  貼り直さないと、個人ID・クラウドの削除が拒否される。
- **問い合わせ先は `CONTACT_URL`（mahjong-scorer.jsx の先頭近く）1か所**。privacy.html にも同じURLがある。
- **ポイント換算の単位は `SAFE_UNIT()` を通して表示する**。円・ドルなどお金の単位は入れられない（ストアの賭博の扱い対策）。
- **初期ルールは 25,000点持ち・30,000点返し・ウマ10-20・テンパイ連荘**（`FACTORY_RULES`）。
  前から使っている人には、初回の起動で前の初期ルール（`PREV_FACTORY_RULES`）を `mj_default_rules` に入れて据え置く
  （見分けは `mj_rules_v2` で1度だけ）。
- **直前の入力の取り消し**（`undoInfo` / `undoLast`）は、入力していない間の局面を控え続け、局が増えたらその控えに戻す仕組み。
  入力中フラグを足したら、取り消しの effect の `inputting` にも足す。
- **開き直したら卓へ戻る**：⏸ で保留したとき（`mj_ongoing_paused`）と6時間より前の対局は、今までどおりメニューから。
- **アガリ入力**：頭ハネ（同時に1人まで）のときは、あがった人をタップしたらそのまま次へ。ロンの相手もタップで確定。

## 作業ルール
- 迷う変更・大きい変更は**実装せず報告に回す**。確実で小さい改善だけをコミットする。
- コミットは変更1件ごとに分け、メッセージは日本語で
  「どの画面・機能」を触ったか明記（例: `ルール確認画面: ○○の説明を実装に合わせ修正`）。
- **git push は絶対にしない**。ローカルコミットまで。
- コミットメッセージや報告にAIモデル名を書かない。
